Consistent Hashing

Hash servers and keys onto one ring; a key belongs to the next server clockwise.

  • Only about K/N keys move when a node joins or leaves — the rest never notice.
  • Virtual nodes (100–200 per server) even out the load the ring would otherwise skew.
  • Used by DynamoDB, Cassandra, Riak, and roughly every CDN you have ever loaded a script from.

No. 037 · System Design

Why does consistent hashing minimise re-mapping when a node joins?

(tap to flip)

No. 037 · answer

Because only the arc between the new node and its predecessor changes owner.

Keys land on a ring, so adding a node steals just the segment behind it — about K/N keys — instead of rehashing all K.
